# LumaRPL port 19.12 — quiet startup time sync

Saved, validated Wi-Fi credentials in /db48x/network/WIFI.cfg enable one startup attempt to synchronize UTC with NTP. No credentials or no SD means no radio startup. No progress screens, notices or error dialogs are opened. A failed attempt preserves the clock. The saved timezone is used, defaulting to Toronto with daylight saving.

The SDK radio driver is initialized once during initial boot before calculator input starts. Wi-Fi association, DHCP, DNS and NTP then progress cooperatively through the calculator input loop, native screen input and Lua input hooks. No connection-wait loops, second core, extra framebuffer or TLS session are introduced. SDK poll/driver timing still requires measurement on the device; host tests do not establish physical latency.

The join window is bounded to 35 seconds; two NTP servers have bounded DNS/reply windows and the overall attempt stops within 55 seconds of the next cooperative poll. There is no repeating background retry or automatic rate download. The radio shuts down after success/failure. An explicit currency refresh cancels the boot attempt before taking radio ownership; manual RTC edits and Forget credentials also cancel it. Late DNS replies cannot access the released client. Temporary credentials are erased on joining or cleanup. Standard NTP remains unauthenticated, as with explicit sync; HTTPS verification is unchanged.

The sync uses at most a 256-byte temporary controller plus existing SDK allocations from the bounded heap, and 8 extra static bytes. Calculator arena 208 KiB, heap 96 KiB, stack 32 KiB, framebuffer 100 KiB and shared workspace 16 KiB remain reserved. New networking and TLS sessions are mutually exclusive.

Also includes port 19.11 Esc Back and the clearer command-reference entries for virtual keypad commands, StackFont, LineWidth and drawing patterns. Existing saved formats and other Help topics are retained apart from the relevant network explanation.

## Checks and limits

Fresh AddressSanitizer/UndefinedBehaviorSanitizer tests execute the production boot controller and SDK adapter with deterministic fault injection: success, authentication/join failures, retries/timeouts, DNS fallback/stale callbacks, bad source/port/cookie, socket/packet/send failures, one-shot delivery, cleanup and millisecond wrap. Existing NTP packet and timezone/wall-clock sanitizer tests run separately. Production UI/RPL/Lua/currency regressions, help indexing, rendering audit, memory and loader checks are rerun. Desktop core is unchanged from port 19.11; its clean 8,447-test baseline is inherited, not a fresh full-suite run. Physical verification and actual input latency remain pending.

## Device acceptance

1. Save network credentials using Settings > Network, and choose your timezone.
2. Restart. Immediately enter calculations and use menus; no network dialog should appear. Check that the displayed date/time updates in your timezone when Wi-Fi/NTP succeeds.
3. Restart outside Wi-Fi range. Continue calculating; no error should appear, and the existing clock should remain untouched. There is no date persistence/RTC change in this release.
4. Start an explicit exchange-rate refresh during startup, then verify conversion and saved-rate reuse.
5. Test a manual clock change during startup, Lua, graphing and loader return.

Build verification is separate from device acceptance. Deployment is a separate action; the SD card has not been modified by this build.
